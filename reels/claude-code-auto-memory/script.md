# 同じ注意、毎回してない？（自動メモリ）

## 企画の狙い

- **誰の何を解決するか**：Claude Code に、会話のたびに同じ注意や好み（使うパッケージマネージャーなど）を打ち直している人の手間を減らす
- **リールで持ち帰れる学び**：「覚えて」と頼むと Claude が自分のメモ（自動メモリ）に残し、メモの目次は次の会話の最初に読み込まれる。チームで守るルールは「CLAUDE.md に追加して」、自分の好みは「覚えて」で使い分ける
- **記事で追加して得られること**：記事は未作成。記憶の4層（会話・要約・CLAUDE.md・自動メモリ）の記事で、目次（MEMORY.md）と中身のファイルの関係、目次の読み込み上限（先頭200行か25KB）、保存場所、オン・オフの切り替え、/compact・/clear の後の扱いまで説明する予定
- **今後もフォローする理由**：コンテキスト管理シリーズの4本目（①AIの記憶の置き場所 → ②CLAUDE.md に書くこと → ③会話の掃除 → ④Claude が自分で取るメモ）。次回は「/clear と /compact で何が残るか」
- **今回試す変更（1つ）**：フックの型（#27 毎回の手間）とテーマ（コンテキスト管理）は実績どおりにして、題材だけ「自分でやる工夫」から「Claude Code に最初からある機能」に変える
- **判断の目安**：シリーズ上位3本の範囲（3秒維持率 34.6〜46.8%、保存率 1.05〜1.17%）に近ければ、「機能の紹介でも、この型とシリーズの流れなら届く」とみる。上位3本は投稿から23〜28日後の累計なので、経過時間はそろっていない。数字は [metrics.md](../../metrics.md)（2026-11-09 時点）

- 本文シーン（6〜8秒）は、4秒ごとに画面を変える（カードの登場・手書き注釈・キャラの表情の切り替え）

## 公開前の確認

- **実機で確かめる**：「覚えておいて：このプロジェクトは npm じゃなくて pnpm を使う」と頼み、保存の表示の文言を確認して画面を合わせる。続けて新しい会話（`/clear` の後でよい）を始め、`/context` で自動メモリが読み込まれているかを見る。結果と Claude Code のバージョンは `sources.md` の検証記録に書く
- **撮影は撮影用のリポジトリで**：自動メモリには進行中の作業や決定も保存される。案件名やユーザー名が入ったパス（`~/.claude/projects/` の下のフォルダ名を含む）を映さない
- **記事への誘導は入れない**：記事がまだないため、動画にもキャプションにも「全手順はプロフのリンクから」を入れていない。記事を公開したら、キャプションにだけ追記できる（動画は投稿後に変えられない）
- **次回予告**：シーン7の「次回：/clearと/compactで何が残る？」は、次の回（記憶の4層）を作る前提。予定が変わりそうなら外す
- 声入れは未定（入れる場合は上のナレーション台本を使う）
